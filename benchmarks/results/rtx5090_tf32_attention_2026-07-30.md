# RTX 5090 TF32 attention

These measurements use JAX 0.11.0 on an RTX 5090 with Ubuntu 26.04, CUDA
runtime 12.8, and NVIDIA driver 580. The workload is `B=1`, `Hq=Hkv=8`,
`D=128`, with float32 inputs and outputs. Mosaic and mapped contractions use
TF32 tensor-core multiplies with FP32 accumulation. Every case is compiled
before timing and runs in a fresh process.

The backward column measures the compiled gradient function, including its
recomputed forward pass. Times below are median forward / backward
milliseconds. Memory is peak allocation above the input-buffer baseline.

## Maximal causal attention

The staged implementation uses a 32x64 producer/consumer forward and 32x32
query-major/key-major backward passes. “Generic Mosaic” is the immediately
preceding 32x32 TF32 implementation. “Mapped” is the best measured tile at
each scale; 1024x1024 won every listed case.

| sequence | staged Mosaic | generic Mosaic | best mapped | XLA | cuDNN |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1,024 | 0.106 / 0.394 | 0.174 / 0.562 | 0.167 / 0.397 | 0.116 / 0.262 | unavailable |
| 2,048 | 0.221 / 0.990 | 0.325 / 1.379 | 0.400 / 1.157 | 0.433 / 1.170 | unavailable |
| 4,096 | 0.646 / 3.095 | 0.916 / 4.300 | 1.163 / 3.491 | 1.573 / 4.474 | unavailable |
| 8,192 | 2.139 / 11.641 | 3.094 / 15.806 | 3.871 / 11.594 | 6.499 / 18.193 | unavailable |
| 16,384 | 8.682 / 47.619 | 11.977 / 57.733 | 16.671 / 44.667 | OOM / timeout | unavailable |

The staged forward is 1.38–1.64x faster than generic Mosaic across this
range. The full backward benchmark is 1.21–1.43x faster. It beats XLA from
2K onward and remains linear-memory at 16K, where XLA forward fails trying to
allocate 8.02 GiB.

| sequence | staged Mosaic MiB | generic Mosaic MiB | best mapped MiB | XLA MiB |
| ---: | ---: | ---: | ---: | ---: |
| 1,024 | 40 / 40 | 40 / 40 | 228 / 248 | 168 / 216 |
| 2,048 | 48 / 72 | 48 / 64 | 228 / 228 | 360 / 560 |
| 4,096 | 64 / 144 | 64 / 128 | 168 / 352 | 1,152 / 1,632 |
| 8,192 | 112 / 289 | 112 / 257 | 320 / 416 | 4,320 / 6,336 |
| 16,384 | 208 / 577 | 208 / 513 | 368 / 832 | OOM / timeout |

Backward staging adds linear-size transposed operand views, accounting for
the modest increase over generic Mosaic while remaining well below mapped and
XLA peaks.

## Unmasked attention

The integrated staged path starts at 4K for unmasked attention.

| sequence | staged Mosaic | generic Mosaic | best mapped | XLA |
| ---: | ---: | ---: | ---: | ---: |
| 4,096 | 1.188 / 6.315 | 1.709 / 8.419 | 1.607 / 4.798 | 1.580 / 4.265 |
| 8,192 | 4.333 / 25.508 | 6.235 / 31.755 | 6.310 / 22.009 | 6.403 / 18.194 |

The staged forward is faster than both mapped and XLA. The remaining
unmasked backward gap is structural: D=128 uses separate dK and dV passes to
avoid the register-pressure cliff of retaining both complete FP32
accumulators. A combined pass and wider tiles were measured, but were slower
and therefore not retained.

cuDNN is unavailable for every row because JAX's cuDNN attention frontend
rejects float32 Q/K/V; its accepted input dtypes are FP16, BF16, and FP8.

## Shape coverage

At 4K causal context, the staged path compiled and ran for every tested width
`D={64,80,96,112,128}`. Wider FP32 heads conservatively use the generic 32x32
kernel; compiled forward and backward checks passed at `D=192,256,512,1024`,
and `2048`.

Representative commands:

```bash
uv run python benchmarks/benchmark_mapped_attention.py \
  --implementation mosaic \
  --seq-len 1024 2048 4096 8192 16384 \
  --batch-size 1 \
  --query-heads 8 \
  --kv-heads 8 \
  --head-dim 128 \
  --dtype float32 \
  --mask causal \
  --warmup 3 \
  --iterations 10
```

```bash
uv run python benchmarks/benchmark_mosaic_backward_components.py \
  --seq-len 4096 \
  --heads 8 \
  --head-dim 128 \
  --dtype float32 \
  --unmasked \
  --split-dkv
```
